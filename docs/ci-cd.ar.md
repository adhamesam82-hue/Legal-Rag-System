# خطة التكامل والنشر المستمرّ — مساران على صندوق واحد

> الحالة عند الكتابة (٣١ أغسطس ٢٠٢٦): الإنتاج يعمل على `alsigil.com` من صندوق
> Hetzner CPX22 واحد. لا يوجد مسار تطوير على الخادم بعد. هذه الوثيقة تصف
> المسارين وكيف يصير الانتقال بينهما ترقيةً لا إعادة نشر.

## لماذا مساران

اليوم `main` تنشر مباشرةً إلى الإنتاج، وحمايتها الوحيدة فحص الدخان والرجوع
التلقائي. هذا كافٍ لصندوق بلا مستخدمين، ويصير غير كافٍ في اللحظة التي يدخل فيها
أول مكتب: أي تغيير يُختبر أول ما يُختبر على بيانات موكّلين حقيقية.

المساران يفصلان سؤالين مختلفين:

| | التطوير (staging) | الإنتاج |
|---|---|---|
| النطاق | `staging.alsigil.com` | `alsigil.com` |
| من يصل إليه | أنت (خلف كلمة مرور HTTP) | العالم |
| متى يُنشر | تلقائيًا عند كل دمج إلى `main` | بقرار صريح منك |
| الهوية | نسخة Clerk تطويرية (أو `LEGALOS_DEV_AUTH`) | نسخة Clerk إنتاجية فقط |
| البيانات | عيّنة مولَّدة + المدوّنة | بيانات المكاتب |
| النسخ الاحتياطي | لا شيء — قابل للمسح بحكم التعريف | ليلي مُعمّى إلى R2 |
| محركات البحث | `X-Robots-Tag: noindex` | مفهرَس |

القاعدة الحاكمة: **الإنتاج لا يستقبل شيئًا لم يعمل على staging أولًا، والصورة
التي تُرقّى هي الصورة نفسها بالوسم نفسه** — لا إعادة بناء بين البيئتين، وإلا
فما اختُبر ليس ما نُشر.

## الكلفة — مقيسة لا مقدَّرة

المكدّس الإنتاجي كاملًا وهو خامل على الصندوق:

| الحاوية | الذاكرة |
|---|---|
| caddy | ١٢ MB |
| api | ٨١ MB |
| web | ٩١ MB |
| postgres | ٣٥ MB |
| **المجموع** | **~٢٢٠ MB** |

المتاح على الصندوق ٢٫٩٨ GB، والقرص الحرّ ٦٦ GB. مكدّس ثانٍ كامل يضيف ~٢٢٠ MB
أخرى — أي أقل من ١٢٪ من الذاكرة. **الفصل الكامل (Postgres ثانٍ مستقل) أرخص من
تعقيد المشاركة**، ويعطي ما لا تعطيه قاعدة مشتركة: ترحيل يفسد على staging لا
يمكنه لمس قاعدة الإنتاج بأي حال، ولا حتى بخطأ في اسم القاعدة.

## البنية

```
                    ┌──────────── Caddy (وحيد) ────────────┐
   alsigil.com ────►│ alsigil.com        → api/web الإنتاج │
staging.alsigil.com►│ staging.alsigil.com → api/web staging │◄── basic_auth
                    └───────────────────────────────────────┘
                                    │
                    شبكة docker خارجية مشتركة: alsigil-edge
                                    │
        ┌───────────────────────────┴───────────────────────────┐
   مشروع compose: prod                        مشروع compose: staging
   /opt/alsigil/                              /opt/alsigil-staging/
   api · web · postgres (حجم pgdata)          api · web · postgres (حجم منفصل)
```

Caddy واحد لا اثنان: هو ما يملك المنفذين ٨٠ و٤٤٣، وشهادتا النطاقين تُصدَران
وتُجدَّدان في المكان نفسه. الاتصال بين Caddy والمكدّسين يمرّ عبر شبكة docker
**خارجية** (`alsigil-edge`) ينضمّ إليها الطرفان، لأن مشروعَي compose منفصلان
ولا يرى أحدهما شبكة الآخر افتراضيًا.

## الملفات المطلوبة

| الملف | الحالة |
|---|---|
| `deploy/docker-compose.staging.yml` | جديد — أسماء خدمات مُلحَقة بـ`-staging`، بلا Caddy، `env_file: /opt/alsigil-staging/.env` |
| `deploy/Caddyfile` | كتلة موقع ثانية لـ`staging.alsigil.com` + `basic_auth` + `X-Robots-Tag` |
| `deploy/provision.sh` | إنشاء `/opt/alsigil-staging/` وملفَّي أسراره، وشبكة `alsigil-edge` |
| `.github/workflows/deploy-staging.yml` | نشر تلقائي بعد كل بناء ناجح على `main` |
| `.github/workflows/promote.yml` | ترقية وسم إلى الإنتاج بقرار صريح |
| `.github/workflows/deploy.yml` | يُستبدَل بـ`promote.yml` |
| `tests/test_deploy_config.py` | تأكيدات على كل ما سبق |

## تدفّق العمل

```
فرع عمل ──PR──► الاختبارات (بوابة إلزامية)
                     │
                  دمج إلى main
                     │
              build.yml: الاختبارات ← بناء صورتين بوسم SHA
                     │
        deploy-staging.yml (تلقائي)
        سحب ← ترحيل قاعدة staging ← تبديل ← فحص دخان على staging.alsigil.com
        فشل ⇒ رجوع تلقائي لوسم staging السابق
                     │
              ✋ تجربة يدوية منك
                     │
        promote.yml (workflow_dispatch، بيئة production بمراجِع مطلوب)
        الوسم الافتراضي = ما يعمل على staging الآن
        سحب ← ترحيل قاعدة الإنتاج ← تبديل ← فحص دخان ← رجوع تلقائي
```

نقطتان تصنعان الفرق:

1. **الترقية تأخذ وسمًا لا فرعًا.** `promote.yml` يقرأ `.current_tag` من staging
   ويقترحه افتراضيًا، فالمُرقّى هو بالضبط ما جرّبته — لا «آخر main» التي قد تكون
   تحرّكت بينهما.
2. **بيئة `production` في GitHub** بمراجِع مطلوب تجعل النشر إلى الإنتاج فعلًا
   واعيًا. تحتاج صلاحية admin على المستودع لضبطها؛ حتى تتوفّر، البديل أن
   `promote.yml` يعمل بـ`workflow_dispatch` فقط — وهو أصلًا حاجز نيّة.

## الأسرار والإعدادات

| | الإنتاج | staging |
|---|---|---|
| ملف الأسرار | `/opt/alsigil/.env` | `/opt/alsigil-staging/.env` |
| ملف الواجهة | `/opt/alsigil/web.env` | `/opt/alsigil-staging/web.env` |
| Clerk | `pk_live_` · `sk_live_` · JWKS المخصّص | نسخة تطويرية `pk_test_` |
| `LEGALOS_ENV` | `production` | `staging` |
| `LEGALOS_DEV_AUTH` | **ممنوع** — حارس الإقلاع يرفض التشغيل | مسموح مؤقتًا |
| Resend | مفتاح حقيقي | مفتاح اختبار أو فارغ |
| restic / R2 | مضبوط | غير مضبوط |

`LEGALOS_ENV` ليس زينة: هو ما يجعل حارس الإقلاع قادرًا على رفض `LEGALOS_DEV_AUTH`
في الإنتاج بدل الاعتماد على انتباه من يحرّر الملف.

## البيانات

- **لا تُنسخ بيانات مكاتب حقيقية إلى staging.** بيئة خلف كلمة مرور واحدة
  مشتركة، بمفاتيح تطويرية، وبلا نسخ احتياطي، ليست مكانًا لبيانات موكّلين — وهذا
  التزام قانوني لا تفضيل هندسي.
- staging يُملأ بـ`scripts/seed_demo_firm.py` ونسخة من المدوّنة (تشريعات عامة،
  لا بيانات شخصية).
- `restore_check.sh` يستعيد لقطة الإنتاج إلى **حاوية Postgres مؤقتة**، لا إلى
  قاعدة staging — فحص الاستعادة يجب ألّا يعتمد على بيئة قد تكون معطّلة.

## ما لا يتغيّر

فحص الدخان، والرجوع التلقائي، وفصل الترحيل في خطوة مستقلة، وتمرير القيم
المُتحكَّم فيها عبر `env:` لا عبر قوالب `${{ }}` داخل الصدفة — كلها تنتقل كما هي
إلى المسارين. `promote.yml` هو `deploy.yml` الحالي بمَعلمة بيئة، لا إعادة كتابة.

## الترتيب المقترح للتنفيذ

1. سجل DNS لـ`staging.alsigil.com` (نفس عنوان الصندوق).
2. `provision.sh`: مجلدات staging وشبكة `alsigil-edge`.
3. كتلة Caddy الثانية بـ`basic_auth` و`noindex`.
4. `docker-compose.staging.yml` ورفع أول مكدّس staging يدويًا.
5. `deploy-staging.yml` تلقائيًا، ثم تحويل `deploy.yml` إلى `promote.yml`.
6. حارس الإقلاع على `LEGALOS_ENV` + `LEGALOS_DEV_AUTH`.

الخطوات ١–٤ تعطيك بيئة تطوير على الخادم اليوم، قبل أن تجهز Clerk الإنتاجية.
